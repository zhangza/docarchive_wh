# 系统管理与支撑模块 — 详细功能设计

> 本文档用于前端 Vibe Coding 开发，聚焦业务流程与功能逻辑，所有数据均为 Mock 数据。

---

## 一、模块概述

### 1.1 模块定位

系统管理与支撑模块是"智行合医"医保基金监管系统的**底座与中枢**，为六大智能体提供规则引擎、知识图谱、政策库、数据接入、组织权限、安全审计、消息督办、运行监控等基础能力，确保系统稳定、安全、高效、可扩展运行。

### 1.2 解决的核心问题

- 监管规则调整依赖开发，响应慢、周期长
- 医保领域知识分散，缺乏结构化知识支撑
- 政策法规更新频繁，引用不准确、不及时
- 多源数据接入复杂，接口状态不可视
- 组织权限管理粗放，关键操作缺乏复核
- 数据安全风险高，操作留痕不完整
- 消息分散、时限督办缺位，任务易超期
- 智能体运行状态不可监控，故障发现滞后

### 1.3 与其他智能体的关系

| 支撑能力 | 服务对象 |
|---|---|
| 动态规则引擎 | 疑点线索管理智能体（规则配置、阈值调整） |
| 知识图谱 | 疑点线索管理智能体（溯源分析、关联研判） |
| 政策法规案例库 | 违规处置智能体、文书生成智能体（法条引用、案例参考） |
| 数据源与接口 | 全智能体（数据供给） |
| 组织与权限 | 全智能体（用户认证、权限控制） |
| 数据安全与审计 | 全智能体（脱敏、加密、审计） |
| 消息与时限督办 | 专项任务管理智能体、违规处置智能体（消息推送、超时预警） |
| 运行监控 | 全智能体（运行状态、性能监控） |

## 二、业务流程

### 2.1 整体业务流程

```
[系统初始化] → 组织人员/角色权限/规则/知识图谱/政策库配置
       ↓
[日常运行]
  ├─ 规则引擎：规则配置→参数管理→试跑验证→灰度发布→全量生效
  ├─ 知识图谱：实体维护→关系管理→图谱浏览→图谱应用
  ├─ 政策法规库：内容维护→版本管理→智能引用→引用统计
  ├─ 数据源：接入配置→接口管理→通道监控→异常告警
  ├─ 组织权限：人员管理→角色配置→权限分配→双人复核
  ├─ 安全审计：脱敏加密→操作留痕→审计查询→安全报告
  ├─ 消息督办：消息中心→分类推送→时限监控→超时预警
  └─ 运行监控：智能体监控→系统监控→告警管理→运维报告
```

## 三、功能详细设计

### 3.1 动态规则引擎

#### 3.1.1 可视化规则配置

**功能描述**
支持专项检查重点违规规则的可视化配置与管理。规则类型：阈值类（超量开药、超标准收费）、比对类（进销存vs结算、病历vs结算）、行为类（分解住院、挂床住院）、关联类（参保人-医生-机构异常关联）。配置要素：规则名称、规则编码、违规类型、适用范围（机构类型/区域/险种）、触发条件（可视化条件构建器）、风险等级、处置建议、生效时间。支持规则模板复用、规则分组管理、规则启停。

#### 3.1.4 版本灰度管理

### 3.2 知识图谱管理

**功能描述**
